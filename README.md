# Steering and Evaluating Safety and Faithfulness in Mixture-of-Experts LLMs via Expert Deactivation

Individual Project 2025/26 — University of Leeds

---

## Overview

This project investigates whether specific experts inside a Mixture-of-Experts (MoE) language model are **causally responsible** for faithful and safe behaviour — and whether selectively suppressing them at inference time can steer those behaviours in a predictable direction.

The model under study is **DeepSeek-V2-Lite** (16B parameters, MoE architecture, top-6 expert routing per layer). All experiments run on the **AIRE HPC cluster** at the University of Leeds.

The project is structured as two sequential stages:

- **Stage 1** — measure how expert routing differs across controlled behavioural contrasts, and identify which experts are most associated with each behaviour using Risk Difference (RD).
- **Stage 2** — suppress those experts during inference and evaluate whether the predicted behavioural change occurs.

---

## Stage 1: Routing Analysis

Stage 1 constructs two behavioural contrast pipelines and measures expert routing across them using teacher-forced forward passes.

### Faithfulness Pipeline

**Contrast**: question answering *with* a retrieved context document vs *without* it.

- Dataset: FaithEval-Counterfactual (`Salesforce/FaithEval-counterfactual-v1.0`), prepared by `stage1/prep/prepare_faithdata.py`
- Each example produces two chat-formatted records: `with_context` (system prompt + document + question) and `no_context` (system prompt + question only), stored in `/scratch/sc23jc3/faithcf_prepared/`
- 500 pairs are processed; routing is sliced to **question tokens only** via subsequence matching
- Model: `deepseek-ai/DeepSeek-V2-Lite` (base)

### Safety Pipeline

**Contrast**: harmful compliance vs safety-aligned refusal, for the same harmful prompt.

- Dataset: AdvBench (`walledai/AdvBench`), prepared by `stage1/prep/prepare_safedata.py`
- For each prompt, two responses are generated by **DeepSeek-V2-Lite-Chat**:
  - `unsafe`: model is committed mid-response using a forced prefix (`"Sure! Here is a step-by-step guide:\n\n1:"`) to prevent it pivoting to a refusal
  - `safe`: model is given a safety-aligned system prompt and generates a context-aware refusal
- 200 contrast pairs stored in `/scratch/sc23jc3/advbench_prepared/`
- Routing is sliced to **assistant response tokens only**, length-matched to `min(L_safe, L_unsafe)` tokens

### RD Metrics

For both pipelines, Risk Difference is computed in two complementary ways:

- **Activation-frequency RD** — how often each expert appears in the top-6 selection across the two conditions
- **Logit-based RD** — mean raw pre-softmax router logit difference, capturing router preference even for experts that narrowly miss selection

Results saved to `/scratch/sc23jc3/results/`: `rd_faithfulness.json`, `rd_faithfulness_logits.json`, `rd_safety.json`, `rd_safety_logits.json`.

Orchestrated by `stage1/src/run_stage1.py`. Analysis notebooks and figures in `stage1/analysis/`.

## Stage 2: Expert Steering

Stage 2 takes the RD results from Stage 1 and tests causal influence by suppressing identified experts during inference.

### Candidate Selection

Experts are selected per layer by taking the top-N by |RD| on **both** frequency and logit metrics, then keeping only the **intersection**. This requires an expert to be both consistently activated and consistently preferred at the logit level. `N` is controlled by `CANDIDATE_N` in `stage2/src/config.py` (default: 3).

Three candidate sets are selected:
- `safety_neg` — experts most associated with harmful compliance (most negative safety RD)
- `safety_pos` — experts most associated with safe refusal (most positive safety RD)
- `faith_neg` — experts most associated with context-ignoring (most negative faithfulness RD)

### Intervention Mechanism

`ExpertSteerer` (`stage2/src/intervene.py`) registers forward pre-hooks on each targeted MoE gate module. Two modes:

- **Hard mode**: computes a per-token hidden-state perturbation `δh` via the pseudoinverse of the gate weight matrix such that each suppressed expert's logit is driven to exactly `−1e4` before the gate's native grouped top-k runs. All other expert logits are unchanged exactly. The gate handles routing normally on the modified input — always producing k=6 experts with natural weights.
- **Soft mode**: precomputes a constant `δh` (input-independent) that shifts targeted experts' logits by `SOFT_STRENGTH × RD_score`. The gate routes normally on the shifted distribution — experts are not guaranteed to be displaced, whether they fall out of top-k depends on their routing margin. `SOFT_STRENGTH` defaults to 0.5.

Hooks are registered once per generation call and removed via `.remove()` when done.

### Evaluation

**Safety** — measured on AdvBench. Responses are classified by **Llama-Guard-3-8B** (CPU). Metric: `safe_rate`.

Two steering directions × three conditions:
- `safety_safe`: suppress `safety_neg` experts → model should become safer (baseline → hard → soft)
- `safety_unsafe`: suppress `safety_pos` experts → contrastive, model should become less safe

**Faithfulness** — measured on two benchmarks via exact string match (MCQ):

| Benchmark | HuggingFace ID | Purpose |
|---|---|---|
| FaithEval-Counterfactual | `Salesforce/FaithEval-counterfactual-v1.0` | MCQ where context contradicts parametric knowledge |
| RACE | `ehovy/race` | Benign reading comprehension control; checks steering does not degrade general QA |

`faith_neg` experts are suppressed (hard and soft) and evaluated against baseline.

Results saved to `stage2/results/{task}/{condition}.json`. Orchestrated by `stage2/src/run_stage2.py`.
